# Homework 02 — User Service

Консольное приложение для управления пользователями на Java с использованием Hibernate и PostgreSQL, без Spring. Второе домашнее задание курса.

## Возможности

- Создание, просмотр, обновление и удаление пользователей.
- Поиск по ID, имени, возрасту, email и дню создания.
- Проверка входных данных и уникальности email.
- Автоматическое заполнение даты создания и сохранение её при обновлении.
- Транзакции, откат при ошибках и закрытие ресурсов.
- Табличный вывод результатов поиска.
- Логирование запуска, завершения, изменений данных и ошибок.
- Обработка ошибок ввода и подключения к БД.

## Технологии

- Java 21 или совместимая с настройками проекта версия JDK.
- Maven.
- Hibernate ORM.
- PostgreSQL.
- SLF4J и Logback.

Версии зависимостей указаны в `pom.xml`.

## Структура приложения

| Компонент | Назначение |
| --- | --- |
| `Main` | Создание объектов, запуск меню, закрытие ресурсов |
| `ui.ConsoleMenu` | Консольный ввод, меню и отображение результатов |
| `service.UserService` | Сценарии работы, валидация и проверка занятости email |
| `validation.UserValidator` | Проверка имени, email, возраста и ID |
| `dao.UserDAO` | Интерфейс доступа к данным |
| `dao.HibernateUserDAO` | Реализация запросов и транзакций через Hibernate |
| `model.User` | Сущность пользователя и отображение на таблицу `users` |
| `HibernateUtil` | Создание и предоставление общей `SessionFactory` |

Консоль вызывает сервис, сервис обращается к DAO, DAO работает с PostgreSQL через Hibernate.

## Подготовка базы данных

Приложение ожидает PostgreSQL на `localhost:5433` и базу `user_service`.

Можно использовать существующий контейнер PostgreSQL с опубликованными портами `5433:5432`. Если PostgreSQL ещё не установлен, пример создания контейнера в PowerShell или Bash:

```bash
docker run --name user-service-postgres -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=change_me -e POSTGRES_DB=user_service -p 5433:5432 -v user-service-data:/var/lib/postgresql/data -d postgres:17
```

Замените `change_me` своим паролем. Если порт `5433` занят существующим PostgreSQL, используйте его либо выберите другой порт и измените URL подключения. Том `user-service-data` сохраняет данные вне файловой системы контейнера.

Для существующего сервера при отсутствии базы выполните отдельно, вне явно открытой транзакции:

```sql
CREATE DATABASE user_service;
```

Затем откройте SQL-консоль именно для `user_service` и проверьте подключение:

```sql
SELECT current_database();
```

В новой базе создайте таблицу:

```sql
CREATE TABLE users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(256) NOT NULL,
    email VARCHAR(256) NOT NULL,
    age INTEGER NOT NULL CHECK (age >= 0),
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT users_email_unique UNIQUE (email)
);
```

Скрипт предназначен для первоначального создания таблицы. Если таблица уже существует, повторно создавать её не нужно. Типы колонок должны соответствовать полям сущности `User`.

## Настройка Hibernate

Создайте локальный файл `src/main/resources/hibernate.properties`:

```properties
hibernate.connection.driver_class=org.postgresql.Driver
hibernate.connection.url=jdbc:postgresql://localhost:5433/user_service
hibernate.connection.username=postgres
hibernate.connection.password=change_me

hibernate.hbm2ddl.auto=validate
hibernate.show_sql=false
hibernate.format_sql=true
```

Укажите реальные параметры своего PostgreSQL. `validate` проверяет соответствие таблицы сущности, но не создаёт и не изменяет таблицы.

Не публикуйте файл с настоящим паролем. Для репозитория можно сохранить `hibernate.properties.example` с заглушкой и исключить локальный `hibernate.properties` через `.gitignore`. Если конфигурация уже отслеживается Git, одно добавление в `.gitignore` не прекратит её отслеживание.

## Сборка и запуск

Команды выполняются из папки `homework-02`, содержащей `pom.xml`:

```bash
mvn clean package
```

Для запуска в IntelliJ IDEA:

1. Откройте `homework-02/pom.xml` как Maven-проект.
2. Выберите JDK, соответствующую настройкам `pom.xml`.
3. Загрузите Maven-зависимости.
4. Запустите PostgreSQL и настройте `hibernate.properties`.
5. Запустите метод `Main.main()`.

Сборка не подразумевает создание исполняемого JAR со всеми зависимостями. Команда `java -jar` требует отдельной настройки упаковки, если её нет в `pom.xml`.

## Меню

| Пункт | Действие |
| --- | --- |
| `1` | Создать пользователя |
| `2` | Открыть подменю поиска |
| `3` | Показать всех пользователей |
| `4` | Обновить пользователя по ID |
| `5` | Удалить пользователя по ID |
| `0` | Завершить приложение |

В подменю поиска доступны ID, имя, возраст, дата создания и email. Пункт `0` возвращает в главное меню.

Имя и email ищутся по точному совпадению. Дата вводится в формате `yyyy-MM-dd`, например `2026-11-15`. Поиск за день использует диапазон от начала выбранного дня включительно до начала следующего дня исключительно.

При обновлении вводятся ID существующего пользователя и новые имя, email и возраст. ID и дата создания сохраняются.

## Валидация и ограничения

- Имя не может быть `null`, пустым или состоять только из пробелов.
- Email обязателен и проверяется на базовое соответствие формату адреса. Существование почтового ящика не проверяется.
- Возраст — целое неотрицательное число.
- ID для поиска, изменения и удаления — положительное число.
- Email должен быть уникальным. При обновлении текущий пользователь исключается из предварительной проверки.

Окончательную гарантию уникальности обеспечивает ограничение PostgreSQL `users_email_unique`. Предварительная проверка в сервисе позволяет раньше сообщить о занятом email.

## Транзакции и ошибки

Операции DAO выполняются в транзакциях. При успехе вызывается `commit()`, при ошибке выполняется попытка `rollback()`. Сессии закрываются через `try-with-resources`.

Ошибки ввода и валидации выводятся пользователю без технического стека. Для ошибок Hibernate/PostgreSQL показывается понятное сообщение, а технические подробности записываются в лог.

При потере соединения откат также может завершиться ошибкой. Безопасный откат сохраняет такую ошибку как `suppressed`, не подменяя исходное исключение.

## Логирование

Настройки находятся в `src/main/resources/logback.xml`.

Логи записываются в `logs/user-service.log` относительно рабочей папки запуска. Записываются запуск и завершение приложения, создание, изменение и удаление пользователей, ошибки БД со стеком исключения.

Предупреждение Hibernate об использовании встроенного пула соединений допустимо для данного учебного приложения. Для промышленного использования требуется отдельная настройка пула.

## Проверка работы

Основные ручные сценарии:

1. Создать пользователя и найти его по ID и остальным полям.
2. Обновить имя и возраст, убедиться, что ID и `createdAt` не изменились.
3. Проверить пустое имя, неверный email, отрицательный и нечисловой возраст.
4. Попытаться создать пользователя с занятым email и обновить email на занятый другим пользователем.
5. Проверить поиск, обновление и удаление несуществующего ID.
6. Удалить пользователя и убедиться, что повторное удаление сообщает об отсутствии записи.
7. Перезапустить приложение и проверить сохранность данных.
8. Остановить PostgreSQL во время работы и выполнить запрос: проверить сообщение в меню и запись `ERROR` в логе.
9. Запустить PostgreSQL снова и повторить запрос.

В ходе ручной проверки подтверждены создание, обновление и удаление пользователей, запись логов, обработка потери соединения и успешный поиск после повторного запуска PostgreSQL.
