### Домашняя работа №1 — собственная реализация HashMap

Необходимо написать собственную реализацию структуры данных `HashMap`.

Обязательные методы:

- `get()` — получение значения по ключу;
- `put()` — добавление новой пары или обновление значения;
- `remove()` — удаление пары по ключу.

### Домашняя работа №2 — консольное приложение User Service

Консольное приложение на Java для управления пользователями с использованием **Hibernate и PostgreSQL**.

Сущность `User` содержит поля:

- `id` — идентификатор;
- `name` — имя;
- `email` — уникальный адрес электронной почты;
- `age` — возраст;
- `createdAt` — дата и время создания, колонка `created_at` в БД.

Реализованные возможности:

- Создание, просмотр, обновление и удаление пользователей — CRUD.
- Поиск по ID, имени, возрасту, email и дню создания.
- Проверка входных данных и уникальности email.
- Автоматическое заполнение даты создания с сохранением при обновлении.
- Консольное меню с подменю поиска и табличным выводом.
- Разделение приложения на консольный интерфейс, сервисный слой и DAO.
- Настройка Hibernate через `hibernate.properties`.
- Управление транзакциями и откат при ошибках.
- Обработка ошибок Hibernate и PostgreSQL.
- Логирование через SLF4J и Logback.

**Технологии:** Java 21, Maven, Hibernate ORM, PostgreSQL, SLF4J, Logback.

Инструкция по настройке базы данных, сборке и запуску находится в [README второго задания](./homework-02/README.md).

### Домашняя работа №3 — тестирование User Service

Продолжение домашней работы №2: добавлены **юнит-тесты сервисного слоя** и **интеграционные тесты DAO**.

Реализованные проверки:

- Тестирование бизнес-логики `UserService` с использованием моков `UserDAO`.
- Проверка валидации входных данных и уникальности email.
- Проверка успешных операций и обработки отсутствующих пользователей.
- Проверка отсутствия обращений к DAO при некорректных данных.
- Интеграционное тестирование `HibernateUserDAO` с PostgreSQL в контейнере Testcontainers.
- Проверка CRUD, поиска и ограничения уникальности email в БД.
- Проверка автоматического назначения ID и сохранения `createdAt` при обновлении.
- Параметризованные тесты для нескольких вариантов входных данных.
- Изоляция тестов: свежие моки и очистка таблицы перед каждым интеграционным тестом.

**Технологии:** Java 21, Maven, Hibernate ORM, PostgreSQL, JUnit 5, Mockito, Testcontainers.

Для запуска интеграционных тестов необходим работающий Docker. Тестовая БД создаётся автоматически.
