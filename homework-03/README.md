# Homework 03 — Тестирование User Service

Проект продолжает домашнюю работу №2: консольное CRUD-приложение для управления пользователями с использованием Hibernate и PostgreSQL.

В рамках этой работы добавлены юнит-тесты сервисного слоя и интеграционные тесты DAO.

## Технологии

- Java 21
- Maven
- Hibernate ORM
- PostgreSQL
- JUnit 5
- Mockito
- Testcontainers

## Структура проекта

```text
src/
├── main/
│   ├── java/org/redfeather/
│   │   ├── dao/          — интерфейс DAO и реализация на Hibernate
│   │   ├── model/        — сущность User
│   │   ├── service/      — бизнес-логика приложения
│   │   ├── ui/           — консольный интерфейс
│   │   ├── util/         — вспомогательные классы
│   │   ├── validation/   — проверка входных данных
│   │   └── Main.java     — точка входа
│   └── resources/        — конфигурация приложения
└── test/
    └── java/org/redfeather/
        ├── dao/
        │   └── UserDaoIntegrationTest.java
        └── service/
            └── UserServiceTest.java
```

## Юнит-тесты сервисного слоя

`UserServiceTest` проверяет настоящий `UserService`, зависимости которого заменены моками Mockito. Подключение к БД не требуется.

Проверяются:

- создание пользователя с корректными данными;
- отклонение занятого email;
- валидация имени, email, возраста и ID;
- получение пользователя по ID и обработка отсутствующего пользователя;
- получение всех пользователей и пустого списка;
- обновление пользователя и проверка уникальности email;
- удаление пользователя;
- поиск по имени, email, возрасту и дате создания;
- преобразование даты поиска в диапазон от начала дня до начала следующего дня;
- отсутствие обращений к DAO при некорректных данных.

Для проверки нескольких вариантов входных данных используются параметризованные тесты.

## Интеграционные тесты DAO

`UserDaoIntegrationTest` проверяет работу `HibernateUserDAO` с настоящей PostgreSQL в Docker-контейнере, которым управляет Testcontainers.

Проверяются:

- сохранение пользователя и автоматическое назначение ID;
- чтение сохранённых данных;
- обновление данных с сохранением исходного `createdAt`;
- удаление пользователя;
- обработка отсутствующих записей;
- получение всех пользователей;
- поиск по имени, возрасту, email и диапазону дат;
- проверки `existsByEmail` и `existsByEmailAndIdNot`;
- ограничение уникальности email в БД;
- сохранение исходной записи после неудачной попытки добавить дубликат email.

## Изоляция тестов

- Перед каждым сервисным тестом создаются свежие моки и экземпляр сервиса.
- Перед каждым DAO-тестом таблица пользователей очищается.
- Каждый тест самостоятельно подготавливает необходимые данные.
- Тесты не зависят от порядка выполнения.
- Интеграционные тесты используют отдельную БД в контейнере.
- После завершения тестов закрывается `SessionFactory`, а Testcontainers останавливает контейнер.

## Требования для запуска

- JDK 21
- Maven
- Установленный и запущенный Docker с поддержкой Linux-контейнеров
- Доступ к Maven-репозиториям и Docker Registry при первой загрузке зависимостей и образа

В интеграционных тестах используется образ `postgres:17`.

Запускать PostgreSQL вручную или создавать тестовую БД не нужно: Testcontainers выполняет это автоматически. Данные подключения тесты получают из контейнера.

## Запуск тестов

Команды выполняются из папки `homework-03`.

Запустить все тесты:

```bash
mvn clean test
```

Запустить только юнит-тесты сервиса:

```bash
mvn -Dtest=UserServiceTest test
```

Запустить только интеграционные тесты DAO:

```bash
mvn -Dtest=UserDaoIntegrationTest test
```

Для запуска интеграционных тестов Docker должен работать.

Отчёты о результатах выполнения тестов находятся в:

```text
target/surefire-reports/
```
